## Purpose

Start a Vue storefront and Thor BFF as one TDK stack, with no local database and no published container ports.

## ADDED Requirements

### Requirement: One store stack
The repo MUST define a single `store` stack with exactly two resources, `thor-bff` and `storefront-web`, and MUST NOT run a database or a cluster.

#### Scenario: Stack contents
- **WHEN** an operator runs `tdk up store --dry-run`
- **THEN** the output lists `thor-bff` and `storefront-web` under the `store` stack and no database service

### Requirement: Resource placement
Both resources MUST live under `services/store/` so `discovery.paths` in `.tdk/project.json` discovers them. `storefront-web` MUST depend on `thor-bff`.

#### Scenario: Discovery
- **WHEN** TDK loads the project
- **THEN** both resources are discovered from `services/store/` and the storefront waits for the BFF

### Requirement: Vue frontend gate
`storefront-web` MUST be a Vue 3 + Vite frontend with `"framework": "vue"` in `service.json`. The repo MUST require TDK CLI 1.3.75 or newer. Generated Vue Vite config MUST stay in `.autogenerated/` and MUST NOT be hand-edited.

#### Scenario: Framework field
- **WHEN** the resource is scaffolded with `--framework vue`
- **THEN** `storefront-web/service.json` contains `"framework": "vue"` and TDK generates the Vue Vite config into `.autogenerated/`

### Requirement: Shared runtime and unpublished ports
Docker, nginx, Traefik, and Tilt MUST be the shared TDK runtime. Container ports MUST NOT be published on `localhost`. The BFF and storefront MUST be reachable through their generated Traefik routes. `tdk networks` MUST list those routes. The repo README MUST document the concrete URLs confirmed after scaffolding, including the generated BFF prefix followed by its service-relative `/health` path. `tdk down` MUST stop the stack.

#### Scenario: Host routing
- **WHEN** the stack is up
- **THEN** the storefront and BFF respond on their generated Traefik hosts and path prefixes and their container ports are not bound on `localhost`

#### Scenario: Tear down
- **WHEN** an operator runs `tdk down`
- **THEN** nothing from the stack is still running

### Requirement: Hot reload
A Vue edit MUST hot-reload without rebuilding Traefik.

#### Scenario: Frontend edit
- **WHEN** an operator changes a Vue file while the stack is up
- **THEN** the storefront updates without a Traefik rebuild
